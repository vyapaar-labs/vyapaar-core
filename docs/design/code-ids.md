# `vyapaar-core` — Canonical Identifiers & Error Taxonomy Reference

Documents `vyapaar-core/src/ids.rs` (canonical strongly-typed aggregate IDs)
and `vyapaar-core/src/error.rs` (the `CoreError` taxonomy).

## Canonical IDs (`ids.rs`)

Promoted into the Shared Kernel from the Domain Heart's in-memory repository
layer so every bounded context (`vyapaar-ledger`, `vyapaar-risk`,
`vyapaar-market`, `vyapaar-exec`) shares identical, strongly-typed IDs instead
of private stringly-typed duplicates (split-brain ubiquitous-language fix).

All four IDs are generated by the `canonical_id!` macro: string-backed,
transparent-serde, ordered (`Ord`), and self-validating by construction (any
owned string is a valid ID).

| Type | Purpose |
|------|---------|
| `ClientOrderId` | Client-side correlation ID minted at order creation, carried through risk gate, execution gateway, OMS, and ledger. Distinct from the broker-assigned `VenueOrderId`. |
| `AlgoId` | SEBI algo-trading registration identifier; every order request, decision, and audit event carries one so the exchange algo audit trail is preserved. |
| `AccountId` | Trading account (live, paper, or backtest) an order, position, or ledger transaction belongs to. |
| `TransactionId` | One double-entry posting (or balanced group of postings) in the general ledger journal. |

API (macro-generated for every ID):

- `new(id: impl Into<String>) -> Self`
- `as_str(&self) -> &str`
- `Display`, `From<&str>`, `From<String>`
- `Serialize` / `Deserialize` (transparent) + `JsonSchema`

`ClientOrderId` additionally supports UUID round-tripping:

```rust
ClientOrderId::from_uuid(u: Uuid) -> Self
impl From<uuid::Uuid> for ClientOrderId
```

## `CoreError` (`error.rs`)

`CoreError` is a `thiserror`-derived, `PartialEq`/`Eq` error enum returned by
the value-object constructors, parsers, and validation entry points:

| Variant | Trigger |
|---------|---------|
| `InvalidExchange(String)` | Unknown exchange code (`FromStr` for `Exchange`). |
| `InvalidCountry(String)` | Unknown country code (`FromStr` for `CountryCode`). |
| `InvalidPrice(String)` | Unparseable decimal price string. |
| `NegativePrice(String)` | `Price::try_new` / deserialization on a negative value. |
| `InvalidQuantity(String)` | Unparseable decimal quantity string. |
| `NegativeQuantity(String)` | `Quantity::try_new` / deserialization on a negative value. |
| `InvalidCurrency(String)` | Unknown currency code (`Currency::from_code`). |
| `Validation(String)` | Structural validation failures (`Decision::validate`, `TraceContext` parsing). |

## Zero-Floats & Zero-I/O

All IDs are plain strings; no numeric fields. `CoreError` carries only
messages. Neither module performs I/O.
